[src/server/application/use-cases/job.use-cases.ts](../src/server/application/use-cases/job.use-cases.ts) — fetches every candidate row plus their experiences/languages/education/skills, then runs `computeJobFit()` sequentially.

### #4 — PostgREST `.or(...)` injection (audit H1) ✅ RESOLVED (2026-05-25)

Search params interpolated into `.or("name.ilike.%${term}%,email.ilike.%${term}%")` filters. Special chars (`,`, `(`, `)`, `*`) break the filter and let an attacker control part of the WHERE clause.

**Affected repositories**:
- `candidate.repository.ts`
- `job.repository.ts`
- `application.repository.ts`

**Implemented**: `escapeOrTerm(term: string)` added to `src/server/infrastructure/database/db-utils.ts` and applied at every `.or()` callsite in `candidate.repository.ts` and `job.repository.ts`. `application.repository.ts` confirmed to have no `.or()` calls. Unit tests in `tests/escape-or-term.test.ts` (9 tests).

### #10 — Audit H5: interview tokens are replay-capable

HMAC tokens have a 10-min TTL but no `jti` / burn-on-use. A captured token can be replayed within the window.

**Action**: add `interview_sessions.token_used_at TIMESTAMPTZ`. On the first `/turn` call, set it. Reject subsequent token validations where `token_used_at` is set and `session_id` doesn't match the bound session. Update [src/lib/interview-utils.ts](../src/lib/interview-utils.ts) (or wherever `verifyInterviewToken` lives) accordingly.

**Effort**: ~½ day (includes migration + test).

## Supabase Security Advisor — decisions log (2026-05-06)

Triage of all 32 advisor items after JWT rotation. Linter rerun confirms expected end-state.

### Errors (28 × `RLS Disabled in Public`) — **acknowledged, intentional**
Architecture has no client-side direct DB access. Every read/write goes through Next.js API routes using the service role key, which bypasses RLS by design. Enabling RLS would add zero security and force boilerplate policies on every table. Documented in CLAUDE.md ("Database → RLS: Disabled on all tables"). Will permanently show as errors in the advisor — ignore.

### Warnings — **all fixed**
| # | Item | Resolution |
|---|---|---|
| W1 | `Function Search Path Mutable` on `public.set_updated_at` | `ALTER FUNCTION ... SET search_path = pg_catalog, public;` ran on live DB. Canonical schema updated to embed `SET search_path` in the function definition. |
| W2 | `SECURITY DEFINER` `public.rls_auto_enable()` callable by `anon` | `DROP FUNCTION public.rls_auto_enable() CASCADE;` ran on live DB — function was Supabase-Studio-generated, not in the canonical migration. CASCADE also dropped the `ensure_rls` event trigger (see Info section). Canonical schema documents that this function and trigger are intentionally absent. |
| W3 | Same function callable by `authenticated` | Covered by W2. |
| W4 | `Leaked Password Protection` disabled | Toggle enabled in dashboard → Authentication → Password Settings. |

### Info — **all fixed**
| # | Item | Resolution |
|---|---|---|
| I1 | RLS enabled, no policy on `hr_dashboard_widgets` | `ALTER TABLE … DISABLE ROW LEVEL SECURITY;` |
| I2 | Same on `jd_parsing_telemetry` | Same. |
| I3 | Same on `job_shortlists` | Same. |

Root cause for I1-I3: a Supabase-Studio-generated event trigger `ensure_rls` was firing on every `CREATE TABLE` and force-enabling RLS, conflicting with this project's RLS-off architecture. The trigger was dropped via the W2 `CASCADE`. New tables created from now on will not have RLS auto-enabled, matching the rest of the schema.

### Live-DB SQL applied (one-time, do not re-run)

```sql
ALTER FUNCTION public.set_updated_at() SET search_path = pg_catalog, public;
DROP FUNCTION public.rls_auto_enable() CASCADE;  -- also drops the ensure_rls event trigger
ALTER TABLE public.hr_dashboard_widgets DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.jd_parsing_telemetry DISABLE ROW LEVEL SECURITY;
ALTER TABLE public.job_shortlists       DISABLE ROW LEVEL SECURITY;
```

Plus Auth → Password Settings → enable "Leaked password protection".
